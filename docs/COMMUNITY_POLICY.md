# Starlight Studio — Community Policy

> **Draft / pre-release policy.** This document expresses our intended guidelines. It is not a final SDK license or a replacement for a future end-user license agreement.

## Purpose

Starlight Studio is designed to simplify the creation and editing of BeamNG.drive mods while respecting both independent creators and the proprietary platform.

## Proprietary core

The application core will be closed-source. This public repository does not grant permission to copy, modify or redistribute Starlight Studio's proprietary source code or application binaries. Independently distributing a modified build containing protected core components requires separate written authorization.

## Community extensions

We plan to support independent plugins, workflow tools, importers, UI themes and other extensions using an official SDK. Which SDK interfaces and source examples are published, and under what licenses, will be clarified before release. No SDK availability is promised yet.

Authors of independently created plugins retain their applicable rights to their code. The ability to create plugins should not be confused with a right to redistribute the Starlight Studio core.

## Attribution and branding

Community plugins may truthfully describe themselves as **“A community extension for Starlight Studio.”** They must not impersonate the project or imply official endorsement.

Any expressly authorized redistribution of a modified application containing Starlight Studio components must credit the original project, identify the independent maintainer, and clearly say that it is an *unofficial, modified version*.

Those conditions do **not** authorize redistribution by themselves.

## User creations

We do not require attribution merely for using Starlight Studio to create original vehicle mods. Creators retain their rights to the original content they create, subject to any existing third-party rights (for example imported game assets).

## Security and transparency

Community extensions should be honest about their capabilities, dependencies and access to user data. Malicious behavior, impersonation and misleading official-update claims are not welcome.

## Future updates

Formal SDK terms, the EULA, and any additional trademark or contributor rules will be published and reviewed before a public software release.
